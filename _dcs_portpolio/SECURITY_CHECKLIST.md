# 외부 제출 전 보안 체크리스트

이 폴더의 문서(`PORTFOLIO.md`, `CASE_STUDIES.md`, `TECH_STACK.md`)는 실제 사내 식별정보(IP,
API 키, DB 접속정보, 실제 인스턴스 ID, 회사/제품명)를 전부 제거하고 일반화한 상태입니다.
하지만 **이 문서들 자체는 안전해도, 제출 과정에서 다른 경로로 정보가 같이 새어나갈 수 있습니다.**
제출 전에 아래 항목을 꼭 확인해 주세요.

## 반드시 확인할 것

- [ ] **가장 먼저**: 이 프로젝트를 외부(포트폴리오/입사서류)에 공개해도 되는지 회사(팀장/보안팀 등)에
      확인했는가? — 재직 중 회사 인프라에서 만든 결과물은 회사 소유일 수 있어, 무단 공개 시
      계약 위반 소지가 있습니다.
- [ ] **스크린샷을 별도로 캡처해서 첨부하려는 경우**: 화면에 실제 IP(`172.30.x.x`, `100.x.x.x` 등),
      실제 인스턴스 ID, 실제 API 키, 실제 서버 호스트명이 찍혀있지 않은지 하나하나 확인
- [ ] **git 커밋 이력을 그대로 보여주려는 경우**: 커밋 메시지나 diff 안에 실제 IP/키/사내 경로가
      남아있지 않은지 확인 (이 프로젝트에서는 실제로 DB 비밀번호가 `.env.example`에 노출됐다가
      `commit --amend` + force push로 긴급 스크럽한 이력이 있습니다 — 즉 과거 커밋에 진짜 시크릿이
      섞여 있었을 가능성이 있으므로, 저장소를 그대로 공유하면 안 됩니다)
- [ ] **실제 GitHub 저장소 링크를 이력서에 넣으려는 경우**: 그 저장소가 private인지, private이라면
      회사 소유 코드가 포함된 저장소를 채용담당자에게 공유해도 되는 상황인지 재확인
- [ ] **면접에서 상세히 설명하게 될 경우**: 실제 회사명/제품명/도메인(예: 특정 산업·특정 서비스명)을
      말해도 되는지 미리 정리해두기 — 이 문서에서는 의도적으로 "업무 컨테이너", "인스턴스" 같은
      일반화된 표현을 사용했습니다.
- [ ] 이 문서들에 나온 아키텍처 다이어그램(mermaid)과 코드 스니펫은 실제 흐름을 보존하되 식별정보만
      제거한 것이므로, 그대로 사용하셔도 되지만 **회사 고유의 업무 로직(특정 파일 포맷, 특정 프로토콜
      상세 규격 등)은 의도적으로 뭉뚱그려 설명**했습니다 — 더 구체적으로 쓰고 싶다면 그 부분이
      영업비밀에 해당하지 않는지 먼저 확인하세요.

## 이미 처리된 것 (참고용)

- 실제 서버 IP, 포트 번호 → 전부 제거하고 "물리 서버", "중앙 서버" 등으로 일반화
- 실제 API 키, DB 비밀번호, OAuth 토큰 → 전부 제거, 코드 스니펫도 플레이스홀더로 대체
- 실제 인스턴스/장비 ID → 제거
- 실제 회사·제품·서비스명 → "업무 컨테이너", "인스턴스", "외부 메신저 플랫폼" 등으로 일반화
- 실제 GitHub 저장소 URL/토큰 → 문서에 포함하지 않음
